# Working with Records

[← Back to Extending the Framework](index.md)

Extension code reads and writes data through four framework objects. They sit above the database, so you work with view columns and let the framework generate SQL, apply security and maintain audit fields.

## Overview

| Object | What it is |
|---|---|
| **`rel.View`** | A view and its metadata — columns, model name, schema, base object. What gets passed into most handlers. |
| **`rel.Record`** | A single row, with the original and modified value of every field. |
| **`rel.RecordSet`** | A collection of records tied to one view. What you load into, and what you save. |
| **`rel.RecordSets`** | A collection of record sets, so several views can be validated and saved together. |

## Loading records

A record set is bound to a view by name:

```csharp
RecordSet oRecordSet = new RecordSet(parms, true, "WfItem_mE");
```

The `bool` after `parms` is **`useExtensionSchema`** — it decides which schema the view name is looked up in. Pass `true` for your own solution's views, `false` for core framework views.

When a save needs to span several views, group them so they commit together:

```csharp
RecordSets oRecordSets = new RecordSets();
RecordSet oRecordSet = oRecordSets.AddNewRecordSet(parms, true, "WfItem_mE");
```

`Load` and every `LoadBy*` overload **replace** the set's contents rather than adding to them, so you can reload the same instance instead of creating a new one.

## Reading and writing values

`Field("ColumnName")` returns a field with a typed property for each value it can hold:

```csharp
int iId       = oRecord.Field("WfItm_WfItemId").ModifiedValueInt;
bool bFlag    = oRecord.Field("WfItm_IsAutoGenerated").ModifiedValueBool;
string sDesc  = oRecord.Field("WfItm_Description").OriginalValueString;

oRecord.Field("WfrTrns_P1Amount").ModifiedValueDecimal = dAmount;
```

**`ModifiedValue…`** is the current value, including anything you have just set. **`OriginalValue…`** is what was loaded from the database — which is how you detect what the user actually changed. There is a matching pair for each type: `Int`, `Int64`, `Decimal`, `Bool`, `DateTime`, `String`.

Column names are the **view column** names, carrying the model's alias prefix — `WfItm_Description`, not `Description`. The View+ screen shows the exact names.

!!!Note Three habits worth keeping
    **Never assign to the untyped `.ModifiedValue`.** Use the typed property. The untyped one is for internal framework use and bypasses type handling.

    **Read into a local before branching on it.** Clearer than calling `.Field(...)` repeatedly, and cheaper.

    **For lookup and foreign-key columns, set `ModifiedValueLookupIntegrationCode`** rather than the raw ID, so the value resolves by its stable code.

## Inserting, updating and deleting

A record carries a pending action. There are three ways to set it.

### Insert

```csharp
rel.Record oRecord = oRecordSet.InitializeAndAddRecordForInsert(
    parms, sSyncKey, sDisplayValue, sIntegrationCode);
```

This creates the record with the view's column defaults, flags it for insert, adds it to the set and returns it.

The first argument is only a **sync key**, used for logging and matching — it is never written to a column. If the view has an Integration-flagged column, pass **`integrationCode`** as well. It is written before the record joins the set, so the record is immediately findable by code. Set it afterwards instead and an upsert loop will insert a duplicate rather than matching the row you just added.

### Update

```csharp
oRecordSet.MarkRecordForUpdate(parms, oRecord, sPrimaryKeyValue);
oRecord.Field("WfItm_Description").ModifiedValueString = sNewDescription;
```

**Call `MarkRecordForUpdate` before setting any fields.** This is not optional — assigning to fields without it does not reliably persist. It throws if the record is already flagged for insert, which is deliberate: an unsaved row has no database row to update.

### Delete

```csharp
oRecord.InsertUpdateOrDelete = Record.Record_InsertUpdateOrDelete.Delete;
```

Just flip the flag on a loaded record. Note that `Record_InsertUpdateOrDelete` is nested inside `Record`, so it must be qualified as shown.

## Validating and saving

Always validate first, and only save if it passed:

```csharp
string sErrorMessage = string.Empty;

if(oRecordSets.Validate(parms, ref sErrorMessage)){
  oRecordSets.Save(parms);
} else {
  errorMessage.AppendLine(sErrorMessage);
}
```

Surface the validation message rather than dropping it — otherwise the operation fails with no explanation for the user.

Skip the round trip entirely when you have not flagged anything. Track a count and only validate and save when it is greater than zero.

## Bulk operations

For clearing many rows, going through load-flag-save is wasteful. A record set can issue a statement directly:

```csharp
Expression oWhere = new Expression();
oWhere.Clause = "SomeColumn = {P1}";
oWhere.SetExpressionParameter("P1", ExpressionParameter.ParameterType.Int, iValue.ToString());

oRecordSet.Delete(parms, oWhere);
```

!!!Note Physical column names here
    Filter expressions use the **base table's** column name, not the view-aliased one — `SomeColumn`, not `Prefix_SomeColumn`. This is the one place the distinction flips, because the statement runs against the table rather than the view.

For copying and deleting records together with their dependents, `rel.View` offers `SaveDeepCopy` and `SaveDeepDelete`. `SaveDeepCopy` returns a dictionary mapping each original to its new key — and because a deep copy can touch several object types at once, filter it by `relView.BaseRelObjectId` to get only the records belonging to your view.

## Notes

- Records carry both original and modified values; compare them to detect real changes rather than re-saving everything.
- A record set bound to the wrong schema will fail to resolve its view — check the `useExtensionSchema` flag first when a load returns nothing.
- Group related changes into one `RecordSets` so they validate and save as a unit.
- Audit fields (created and modified by, and when) are maintained by the framework. Do not set them yourself.
